# Comprehensive README Design

## Goal

Turn the Intentional UX README into a task-first field guide that helps a new user understand the philosophy, install the package, run a review, interpret its evidence, and contribute without reading the skill internals first.

## Audience

The primary reader builds or reviews digital interfaces with Codex or Claude Code. They may know conventional UX language but should not need prior knowledge of the task tuple, graph model, metric vector, or report contract.

## Reading path

The page begins with the central idea: accessibility and usability reduce latency between intention and outcome. It then moves through one practical sequence:

1. Name the person, input mode, start, outcome, and success evidence.
2. Draw the task path and classify interactions.
3. Evaluate the nine-component metric vector without combining it into one score.
4. Separate measured, observed, and assumed evidence.
5. Produce recommendations with causal findings and exact verification.

A compact worked example makes the method concrete before the page shifts into installation and reference material.

## Required sections

- The intention-to-outcome premise and who the package helps.
- The four-part task tuple and state graph.
- Required, redundant, corrective, confirmation, wait, and context-switch costs.
- The nine-component metric vector, including the distinction between Integrity and frontend integrity.
- Fitts's law limits: calculate only from measured distance and effective width.
- Surface economy guardrails for discovery, keyboard access, recovery, and user control.
- Accessibility routing and incorporation of alternate task paths.
- A complete worked example with evidence levels and a before/after path.
- Expected review output and recommendation fields.
- Codex, direct-skill, and Claude Code installation.
- Example prompts, repository map, validation commands, scope boundaries, contributing, attribution, and license.

## Voice

Use direct, specific prose with varied sentence length. Keep the phrase “latency between intention and outcome” because it names the project precisely. Avoid inflated claims, defensive contrast pivots, corporate filler, fake performance numbers, and a closing paragraph that merely repeats the introduction.

## Acceptance

The README must agree with every manifest and reference contract, retain all existing installation safety guards, contain no universal `codex plugin` CLI claim, pass the structural validator and plugin validator, and pass a Humanize scan plus manual rhythm review.
